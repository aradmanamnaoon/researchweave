## Follow-up: orphaned OS-keyring entries and disconnect safety (isolated)

The preceding same-profile endpoint lock was insufficient after `cloud.profile.disconnect`: historically, disconnect removed the profile from local metadata while leaving the secret in the OS keyring. Reusing the now-vacant ID could have silently sent those existing credentials to a newly configured destination. The new bounded follow-up closes that lifecycle hole:

- `cloud.profile.disconnect` refuses when credentials are still present or the credential store is unavailable. A separate explicitly approved `cloud.credentials.delete` is required first. It **never silently deletes keys**, even on a failed disconnect.
- When a new profile ID is configured for the first time in the current metadata, the actual local-write execution refuses if any orphan keyring entry for that ID is detected or credential-store access fails. The nonmutating preview does not touch keyring secrets and may therefore succeed before the actual write is refused; this is intentional fail-closed behavior.
- `cloud.credentials.store` refuses credentials for unknown/unconfigured IDs, preventing new orphan secrets through the public handler. Errors/receipts remain redacted. No S3/network call is executed.
- A new regression tests an orphaned credential ID, confirms preview nonmutation, verifies execute and premature secret-storage rejection without disclosing secret values, and checks a separate credential deletion permits a fresh validated profile. Existing persisted-profile tests now verify that disconnect cannot succeed until keys are independently deleted.

All edits are restricted to the isolated cloud branch and this QA document. Local Rustfmt, whitespace, and five cloud-profile Python source-contract tests passed. **New Rust regression compilation and execution remain unverified pending exact-source hosted quality.** This is backend security hardening only: it does not implement end-user credential UI, remote CAS capability, encrypted network sync, or native second-device restore.
