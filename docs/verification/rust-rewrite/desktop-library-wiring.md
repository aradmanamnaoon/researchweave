# Desktop Library workflow and Windows UIA release-gate evidence

The Slint Library destination (page 5) now supports user-entered UTF-8 text sources with titles and a refreshable real source list. Actions dispatch through `CommandRouter` to the existing `researchweave-library::LibraryHandler`, with revision-scoped one-use approval for writes, audit records, and persisted sources in the project SQLite store. Results are read from the actual handler output. The display revision updates after successful writes.

The current `LibraryHandler` requires a project folder named by its UUID directly under its workspace directory. New managed projects now finalize to that structure. Custom-location projects with other directory names remain unsupported for library actions and show an explicit error; project creation and reopening still work for those locations. Question and Protocol currently lack matching Rust mutation handlers, so those placeholders were left unchanged.

The reported UIA failure looking for `Create default project` did not reproduce against the local rebuilt desktop. A later run intermittently missed `PDF Reader workspace screen` following activity navigation; retrying the identical UIA smoke passed. The UIA test now waits up to 1.5 seconds for newly created accessibility elements during navigation. This addresses UI Automation tree update timing rather than removing the assertions.

Verification on Windows: desktop unit test suite **8/8 passed**, including native library source add/list/reopen audit and revision persistence; `cargo fmt --package researchweave-desktop --check`, `cargo clippy -p researchweave-desktop --bin researchweave-desktop -- -D warnings`, and `cargo build -p researchweave-desktop` passed. Native Windows UIA smoke passed on the rebuilt executable on the second run. The new source import form has not yet been exercised end-to-end through UIA; backend wiring has been exercised through the real audited command router in unit tests.
