# F31: inert Quarto source projection (partial)

Source: `crates/researchweave-evidence/src/quarto_source.rs`, exposed as project-scoped read-only operation `writing.quarto_source_preview` in `EvidenceHandler`.

Inputs are a verified, current project UUID and a complete bounded `researchweave-manuscript-ast-v1` document. The existing strict `ManuscriptDocument::from_value` validator enforces canonical schema/UUID references, nested text bounds and disallows control/bidi-spoofing characters. A supplied expected project revision is checked before creating the preview. The operation is zero-write, offline, deterministic, and includes project revision, source AST SHA-256, generated Markdown bytes SHA-256, and source-only `.qmd` preview.

The projection supports headings, paragraphs, strong/emphasis inline, ordered/unordered lists, tables and Unicode text. User text is escaped as inert Markdown/HTML text, YAML title is JSON-double-quoted, and the file header contains `format: html` and `execute.enabled: false`. Citation UUIDs are emitted only as explicitly **unresolved text markers**; page breaks generate explicit loss codes. This is a deliberately lossy source projection, **not a verified WYSIWYG, bibliography, Word-compatibility or PDF compilation workflow**. The read-only preview never invokes Quarto, LaTeX, shell, kernel, execution engine or network, nor does it save files or run code cells. The flags `renderer_invoked=false`, `executable_cells_present=false`, `citations_resolved=false`, `persisted=false` are explicit in command output.

Native project binding tests require exact project ID, reject stale expected revisions, compare preview and execute, reopen the project, confirm project revision and event count remain unchanged, and reject unvalidated bidirectional controls. Pure renderer tests cover Unicode, malicious TeX strings and raw HTML, deterministic SHA-256, tables/list structure, explicit projection losses, invalid heading and malformed citation. The existing evidence crate full test suite and strict Clippy are the source-quality gates.

## Newly authored persisted-manuscript `.qmd` physical export

A new native Manuscript flow reads the actual persisted section history through `writing.inspect`; it refuses missing/mismatched manuscript identity, duplicate names, invalid revision/section count, non-array citations, altered body SHA-256 and stale project revision. It converts only verified heading and plain body text into the strict AST using `manuscript_quarto_source.rs`. The UI explicitly reports **missing author title-page data, missing original rich formatting and missing citation positions**: a title synthesized from a manuscript ID is not the author's true title, and citation positions cannot be invented.

`physical_export.rs` prepares the inert Quarto source under the inspected project revision, checks format/flags/source/output SHA-256, and exposes a **separate** non-overwriting `.qmd` Save action with the existing one-use `SensitiveExport` approval, re-rendering, exact destination extension, atomic `create_new(true)`, on-handle SHA-256 readback and audit receipt. Preparing remains zero-write; only explicit Save can create the file, and existing files can never be replaced. This is *local source delivery*, not executing Quarto, creating HTML/PDF/DOCX or uploading anything. Revisions changed between inspection, preparation and final Save are rejected. Synthetic unit tests and a Windows installed-UIA positive/no-overwrite regression were authored; neither constitutes completed latest-source native acceptance until the CI runner actually passes and the saved `.qmd` is inspected.

**Acceptance remains PARTIAL:** No full structured rich Quarto editor, real Quarto execution/sandbox, compiled HTML/PDF/DOCX, TeX engine, citations bibliography integration, exact page-break fidelity or four-platform installed GUI acceptance. Original plain manuscript sections are a lossy input, not full Word-like authoring. Never market this implementation as complete F31 parity.
