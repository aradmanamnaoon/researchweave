# F07 explicit Crossref DOI metadata lookup — partial backend

`crates/researchweave-library/src/crossref_doi.rs` exposes `reference.crossref_doi_lookup` with **`Effect::ExternalNetwork`**, not a harmless `Read` effect. The central dispatcher requires a matching, one-time approval to execute. The module independently requires `allow_network=true`. Preview is guaranteed offline and produces a fixed-host request description with `network_requests=0` and `automatic_reference_update=false`.

Only a conservative ASCII DOI is accepted. The executable lookup contacts fixed `https://api.crossref.org/works/{percent-encoded-doi}` over TLS, with redirects disabled, an eight-second deadline, 256-KiB response cap, `Accept: application/json` and a versioned `User-Agent`. It refuses arbitrary hosts, custom URLs, HTTP 404/429, redirects, corrupted/unexpected JSON, malformed DOI identities and mismatched returned DOI. No retry, reference update, bibliography merge, automatic registration, external author identity inference or disk write occurs. On success it returns selected bounded title/publisher/work-type/up-to-24 author candidates, exact Crossref response SHA-256 and retrieval timestamp. Raw abstracts are excluded. Returned publisher-supplied metadata is **not** independently verified bibliographic truth or peer-review certification.

Sources: Crossref official endpoint https://www.crossref.org/documentation/retrieve-metadata/rest-api/ and rate/access rules https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/ . Crossref's public tier has concurrency/rate limits; a bounded cache and user-facing rate controls must be implemented before production-scale polling. ORCID public API access terms/quotas are separately documented at https://info.orcid.org/documentation/integration-guide/registering-a-public-api-client/ ; **ORCID lookups are not implemented** and commercial eligibility cannot be assumed.

Default local tests cover DOI/host restrictions, malformed/mismatched response refusal, excluded abstract fields, project UUID/expected revision, source event/DB nonmutation, offline preview and independently required `allow_network=true`. The separate **ignored** live test references only published public DOI `10.1038/nphys1170` and never a user's project identifiers; ordinary CI remains fully offline. The user-authorized one-time Windows network smoke passed on 2026-11-01 (`cargo test --offline --locked -p researchweave-library optional_real_public_crossref_read_only_smoke -- --ignored --nocapture`, **1 passed, 0 failed**, actual HTTPS response DOI matched and temporary local project revision/events remained unchanged). This is live public-API connectivity evidence, not a benchmark or a provider-accuracy proof.

The native References surface now also contains an opt-in Crossref DOI panel with a distinct **offline Preview** and **Fetch once (external network)**. Only a successful preview of the **exact current input and project revision** stages an approved request; edited inputs, project switch, stale project revision or failed preview invalidate it. Network fetch uses the project's central one-use `ExternalNetwork` router approval, runs on a worker thread (no UI freeze), and returns only unverified candidate output. The current request generation is compared on completion, so an old project's async response cannot be shown as the newly opened project's result. No Auto Apply/Merge exists. The native panel and source changes **have not yet passed installed Windows/Linux/macOS GUI acceptance**; no such claim is made.

The Windows UIA and isolated Linux AT-SPI suites now also contain an **offline-only** installed References consent-panel scenario: invalid DOI refusal, valid public DOI offline preview, exact project event/revision no-write proof, and an accessible separately enabled Fetch button that they **never click**. This avoids unintended external traffic, unapproved metadata transfers, and nondeterministic public API dependency in unattended native CI. The Linux native release candidate explicitly requires its F07 acceptance marker. These are written test expectations, **not** observed native passes until a matching full installed run completes.

Still missing: project-specific encrypted metadata cache, provider rate-limit policy at production scale, ORCID support, human-approved reference writes and cross-platform installed end-to-end network/offline error testing. The feature remains **PARTIAL**, not a complete DOI/ORCID resolver or release acceptance.
