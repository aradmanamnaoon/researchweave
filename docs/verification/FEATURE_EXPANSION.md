# ResearchWeave feature expansion matrix

Snapshot: 2026-10-26. This is the living implementation map for the 45 expansion slices in `docs/research/COMPETITIVE_FEATURE_PARITY.md`. It intentionally distinguishes backend capability, desktop reachability, and end-to-end acceptance. `VERIFIED_LOCAL` means an exercised local workflow; `IMPLEMENTED_TESTED` means the relevant Rust path has focused tests but may not yet have complete desktop acceptance; `PARTIAL` means useful pieces exist but the requested product workflow is incomplete; `MISSING_TARGET` means no defensible end-to-end implementation claim is available from the live tree.

## Expansion ordering from the live gap map

The highest-value local slices are not the largest missing subsystems. Trusted mixed-method host composition and the first deterministic analysis-report workflow are now implemented. The next vertical slices should reuse those trustworthy persistence/export boundaries: (1) structured manuscript document model + citation nodes, (2) plot/table report items and host-file export, (3) source-grounded AI actions inside manuscript/evidence workspaces, (4) deeper dataset/statistics dialogs, and (5) cross-workspace research-object linking. New network-heavy discovery, executable kernels, media coding and Bayesian breadth should remain later until the core research object graph and report/export contracts are stable.

No row in this matrix changes the release gate by itself. Cross-platform GUI, live Iranian S3 sync, security/SBOM and final package evidence remain mandatory.
