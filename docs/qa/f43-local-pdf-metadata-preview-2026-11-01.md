# F43 read-only local PDF metadata preview — initial backend slice

Source: `crates/researchweave-library/src/pdf_metadata_suggestions.rs`, registered as project-scoped `reference.pdf_metadata_preview` with `Effect::Read`.

Input is the selected project UUID and a previously indexed PDF `source_id` UUID. The handler rejects deleted or non-PDF sources, missing indexed text, oversized text, corrupt extraction-body SHA-256, malformed source digest, mismatched expected project revisions, and missing/corrupted/symlinked hash-addressed project source blobs. It verifies the bytes of the **stored project source object** against its SHA-256, and separately checks the indexed extracted text hash; these are not the same as proving the original external PDF bytes or bibliographic identity. It does not perform network I/O or infer source identities from a filename. It scans at most 32 KiB of already extracted text to offer a weak first-line title hint and bounded literal `10.<registrant>/<suffix>` DOI-pattern matches, with case-insensitive deduplication, Unicode-safe scalar offsets, source/extraction SHA-256, and explicit ambiguous/missing DOI state. These are **unverified candidates only**, not validated bibliographic metadata.

It never writes or merges project references, applies DOI matching automatically, runs Crossref, or verifies the original PDF object bytes. Its output states `preview_only=true`, `automatic_reference_update=false`, `external_doi_verified=false`, `source_pdf_object_bytes_reverified=false`, and requires actual human inspection/approval before any future write. No journal/publisher verification, confidence calibration, citation correctness, PDF page geometry or native GUI workflow is claimed.

Tests cover Unicode title text, literal DOI finding/deduplication, malformed DOI refusal, project-scope/revision refusal, stable reopen, preview=execute read-only output, real project SQLite index receipt, separately corrupted stored object bytes and extracted-text SHA refusal, and no project revision or audit event mutation. The indexed PDF text is a **synthetic fixture**: these tests do not prove correct extraction from actual PDFs.

The native References workspace now includes an explicitly optional, read-only indexed-PDF metadata inspector at the **end** of the deduplication UI. Its UUID field, Preview button and read-only TextEdit are accessibility-labeled. The callback only invokes the project-scoped `reference.pdf_metadata_preview` read operation and renders a refusal or clearly unverified candidates; no Apply action exists and no reference can be silently modified. The inspector is destroyed/reset on project change, protecting project-specific display state. Placing it after existing dedup controls preserves established keyboard tab order through F14.

Status remains **PARTIAL**. Source compilation alone does not prove installed native accessibility, PDF extraction fidelity, trusted reviewer approval, or external validation. Those must pass on the final Windows/Linux/macOS installers before any F43 completion claim.
