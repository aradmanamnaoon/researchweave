# ResearchWeave competitive feature parity and expansion backlog

**Research snapshot:** 2026-10-26. **Scope:** official product documentation and a read-only inspection of the live Rust tree. This is a planning and verification matrix, **not** a claim that ResearchWeave already matches any product. Features documented by a vendor can depend on edition, subscription, platform or version. UX and performance notes below are design inferences from documented interaction models; they are not independent benchmark results.

## Evidence and status convention

- **Implemented API** = a capability name and code path were observed; does not establish functioning desktop interaction or scientific equivalence. **Partial** = some relevant functionality observed, but the stated end-to-end workflow is not demonstrated. **Unverified** = no proof was collected in this audit. **Missing/target** = a feature to implement and validate; never interpreted as a claim of absence from every concurrent branch.
- **P0** protects essential scientific correctness, traceability, data safety and end-to-end writing/review. **P1** covers major research workflows. **P2** covers advanced depth. **P3** is exploratory breadth.
- **S** = narrow feature, **M** = multi-module feature, **L** = major subsystem, **XL** = sustained product area. Dependencies include explicit standards and independent testing. The latest §40 acceptance ledger is an *acceptance requirement*, not automatic evidence of completion.
- Evidence inspected: `crates/researchweave-library/src/lib.rs` (source CRUD, literal local search, bibliography, collection, reference/citation routes), `crates/researchweave-evidence/src/lib.rs` (evidence routes), `crates/researchweave-analysis/src/lib.rs` (analysis domain), `crates/researchweave-ai/src/lib.rs` (AI domain); `crates/researchweave-desktop/ui/main.slint` exists. Recheck live code, integration tests and GUI screenshots at implementation time: parallel workers are changing this tree.

## Design decisions and constraints

1. **One research object graph, specialized views.** Use stable IDs for sources, references, documents, claims, dataset revisions, analyses, annotations and outputs; preserve normalized ownership, citation provenance and traceable source hashes. A familiar interface is an interaction pattern, not copying proprietary assets or branding.
2. **Scientific correctness before surface imitation.** Never advertise SPSS/JASP methods because a menu entry exists. Require reproducible independent oracle datasets with stated tolerances, seeds, missing-data treatment, effect size and assumptions.
3. **AI is a proposed, inspectable operation.** Attach model identity, prompt, source revisions, retrieved spans, confidence limitations and action approval. Design honest abstention behavior for absent sources and contradictory evidence.
4. **Import/export is a contract.** Declare formats, field mappings, lossiness and round-trip scope for DOCX, PDF, RIS, BibTeX, CSL, CSV, XLSX, ODS, SAV, DTA and interoperable schemas; reject silently destructive migrations.
5. **Responsive and accessible by construction.** Virtualize big tables/graphs, batch retrieval, permit keyboard-only paths, expose accessible names/roles/states, provide strong focus indicators, high contrast, non-color encoding and 200% text scaling. Measure p50/p95 navigation, file-open and editing latency on declared machine/file fixtures instead of saying “faster than Word”.
6. **Release evidence only from observed tests.** Separate unit-tested Rust handlers, CLI integration, end-to-end desktop automation, real screenshots and platform-packaging verification. Preserve open §40 gaps until acceptance.
