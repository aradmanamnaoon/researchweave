# Rust AI provider operation parity (2026-10-25)

The Python `AIFacade` manages persistent model configurations, active profile selection, conversation history, provider health services, usage diagnostics and approved agent workflows. The Rust `researchweave-ai` crate provides validated profiles, local and hosted model adapters and proposal-only chat; it does not yet own durable storage or authenticated provider status APIs.

The host `CommandRouter` can register three Rust operations: `ai.profile.validate` (read), `ai.providers.list` (read) and `ai.chat.propose` (external network). `ai.providers.list` receives `{"profiles": [...]}` from a host-controlled configuration store, validates every complete `ProviderProfile`, rejects duplicate IDs and malformed/unknown inputs, and returns only ID, kind, model, local flag and declared capabilities. The `health` field is explicitly `not_checked`; enumeration never resolves credentials, contacts a provider, or reveals endpoints/credential references. It does not claim model availability. An empty configuration is valid.

`ai.chat.propose` already sends model messages over the bounded transport and returns assistant text, provider-reported usage and inert tool proposals behind the existing network approval and egress policy. No returned proposal is executed by this crate. The new catalog operation deliberately avoids persisting secrets or conversations; durable profile/conversation management requires a host-controlled store with project isolation and migration rules, and true health checks require authenticated provider-specific requests and clear network consent. Neither feature is claimed complete.

Validation: `cargo test --locked -p researchweave-ai` (13 unit/integration tests passed), `cargo fmt -p researchweave-ai -- --check`, and `cargo clippy --locked -p researchweave-ai --all-targets -- -D warnings` passed locally on Windows. Tests cover catalog privacy, duplicate and unknown-field rejection, offline behavior, proposal nonexecution and local/mock hosted transports. No live provider credentials were used.
