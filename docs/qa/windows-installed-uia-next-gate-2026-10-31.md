## Worker test-harness changes

Only `crates/researchweave-desktop/tests/windows-uia-smoke.ps1` was changed:

1. `Named` tolerates a transient `ElementNotAvailableException` while Slint replaces accessibility nodes, checks for an unexpectedly exited process before retrying, remains bounded by 50 x 100 ms, and reports up to 35 live controls if the named control is still missing. It does **not** accept an absent control as success.
2. `WaitForNameLike` similarly aborts early on application exit and tolerates a transient tree rebuild while retaining the original timeout and positive matching assertion.
3. After successfully testing the real Dashboard Ctrl+K keyboard shortcut, the script uses the freshly focused **live** Command palette element for navigation and reacquires the palette after navigating to About. This avoids retaining a node across page transitions and still requires real keyboard focus.
4. UIA launch happens within the main `try`; on test failure, the script preserves the original exception and attempts to capture the requested CI screenshot before forcibly closing the test process. Screenshot failure emits a warning but never converts a failed test to a pass.
5. The `PreserveProjectDirectory` safety guard now requires a separator after `target/performance-fixtures`. Paths such as `target/performance-fixtures-sibling` no longer satisfy the accepted-root prefix.
6. For the newly observed freeze viewport failure, `Invoke-ProtocolFreezeButton` uses an accessible button in the real Protocol work-area focus order (the failed CI tree specifically exposed `Preview protocol amendment`, `Save prepared protocol Markdown without overwrite`, `View protocol Markdown export`, and earlier actions). It selects the nearest currently visible button, then uses real Windows Tab/Shift+Tab focus to expose the off-viewport freeze action. Traversal is limited to twenty steps and requires the exact target to receive focus before invoking it. The existing unfrozen, preview-only, approved persisted frozen baseline, SHA-256, version, disclaimer, and duplicate-freeze assertions remain intact. It additionally waits for the native `protocol.freeze_status` read's `Local protocol baseline status verified against persisted history` success message after both inspections and verifies the persisted `event_hash` and `snapshot_sha256` as distinct 64-character hexadecimal receipt fields. The handler source is `crates/researchweave-desktop/src/main.rs:4408-4444` and the persisted evidence implementation is `crates/researchweave-evidence/src/protocol_freeze.rs`. If no Protocol work-area anchor or target is accessible, the check still fails rather than accepting or omitting the freeze workflow.

The `packaging/rust/windows-installed-smoke.ps1` installer wrapper was reviewed and left unchanged. It already propagates the UIA child exit code as a failing release gate; the new failure screenshot is passed through its existing `-Screenshot` argument. It cleans the test installation using an installer-owned path under `target` and verifies persisted test user data after a successful uninstall.
