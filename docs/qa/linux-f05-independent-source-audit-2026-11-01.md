## Remaining risks, limitations and minimal suggestions

1. **P2 — true cross-project isolation not exercised.** F05 tests refusal of the fixed valid-but-**unregistered** UUID `00000000-0000-4000-8000-000000000001` (current script ~301–316), not a genuine **registered reference in another project**. This is valuable a negative missing-ID gate, but cannot substantiate a separate-project citation-leakage claim. If release acceptance requires the latter, register a second synthetic reference through **project B's audited native UI**, verify B's stored UUID, reopen project A, preview B's ID and assert native refusal plus unchanged project A and B events, manuscript versions and reference rows. Do not seed SQLite manually. Avoid this extra UI flow in the primary F05 acceptance run unless deliberately scoped to prevent additional CI instability.
2. **P2 — brittle fixed sleeps/status polling.** Lines ~199,212,254–256,305,321,339,397–411 wait 0.2–0.35s; only autosave persistence uses a finite 30×0.3s poll (~9s), despite a native 800ms debounce and variable CI load. The exact status strings match Rust, but late native accessibility-tree materialization can cause unnecessary false negatives. Minimal patch: use a **bounded 2–4s wait** for each exact named status or field after an action, while retaining the same refusal, body, hash and SQLite assertions. Distinguish “not exposed on time” from “operation actually refused”. Do not replace real checks with indefinite retries or assume success from a click.
3. **P2 — read-only proof is event/manuscript scoped, not a full SQLite snapshot.** The negative/positive preview compares the full **event metadata** plus `f05_saved_abstract()` and the visible body (current script ~311–335), but does not compare the `reference` row's original raw/metadata/status or other tables before and after preview. The actual host routes to project-bound library read and has no preview-write path in the inspected source, so **no product write defect is established**; however, the broader claim “no project data changed anywhere” is not independently proven by the test. Minimal optional stronger check: snapshot the disposable registered reference's `id,title,authors_json,year,doi,kind,format,raw,metadata_json,status` before invalid/valid preview and require exact equality afterwards. No direct modification.
4. **P2 — status/output and interaction safety.** `activate_bounded_control()` first verifies exact accessibility name and physical coordinates inside a private `1280×800` viewport; `activate()` reacquires the control and may fall back to an Xvfb physical click after an AT-SPI action refusal (current script ~101–140,376–408). This should not be treated as proof of successful native callback by itself. F05 mitigates it with real receipt + SQLite checks. Future harness hardening can require rechecking the same node's geometry immediately before fallback clicking, avoiding stale/offscreen matches. No user-visible window is touched by the planned private-Xvfb CI flow.
5. **Scope wording:** A new same-process `Open project` + explicit saved-outline selection proves the current GUI can **select** a persisted immutable section and display the expected body; it does **not** prove a full application kill/relaunch. Treat that distinction explicitly in all release reports. The missing-reference negative does not cover a valid UUID registered in a *different* project. A local reference is not a verified scholarly citation.
