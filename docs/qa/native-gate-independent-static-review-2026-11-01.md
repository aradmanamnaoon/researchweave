### P1 risk, conditional: Linux F03 demands readable AT-SPI `TextEdit` for its positive history gate

The F03 test **unconditionally** calls `read_field(app, "Copyable source-bound reviewer comment history and preview")` after Load (`scripts/qa/mission-atspi-navigation.py:539-551`). `read_field` requires an exact accessible name and a working `queryText()` (`:66-75`), and there is no fallback. The corresponding Slint control is a read-only `TextEdit` (`crates/researchweave-desktop/ui/main.slint:2690-2697`). The *same* AT-SPI runner explicitly documents that some installed Slint `TextEdit` controls exist but do not support `queryText`, falling back to SQL/status only for F14's **empty** scan (`scripts/qa/mission-atspi-navigation.py:2105-2116`). Therefore any hosted build with that documented accessibility behavior must abort during F03 **before** reaching the later F14 positive gate (`:2151-2157`). Whether the current packaged Linux build exposes `queryText` for this particular F03 widget is **not established by source**; this is a conditional failure, not a proven failure of the current binary.

**Minimal fail-closed correction:** when AT-SPI `queryText` is unavailable for the F03 history `TextEdit`, accept no guessed text. Either (a) exercise the actual focused native field via a tested accessibility retrieval mechanism and parse exact persisted JSON, or (b) explicitly mark UI text readback unavailable while checking the exact `manuscript_comments` rows, one redacted `writing.comment_record` event, source hash and revision through the disposable project's SQLite; keep a *separate* explicit accessibility-readback gate so SQLite verification cannot be misrepresented as successful AT-SPI text exposure. Surface the failure mode distinctly in CI artifacts. Prefer option (a) for the full native accessibility gate.
