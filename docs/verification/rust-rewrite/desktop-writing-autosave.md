# Desktop notebook and manuscript autosave

The Slint notebook and manuscript editors now journal each change in bounded, project-ID-keyed local application storage before scheduling an 800 ms single-shot save. The timer restarts on subsequent edits. The save uses `evidence_preview_at` then `evidence_execute_pending`, including the existing revision/CAS and local-write approval/audit checks. One timer flushes both dirty surfaces, so consecutive edits in either editor are coalesced. Notebook saves are accepted without metadata; manuscript saves require a nonempty manuscript ID and section. Invalid or conflicting edits remain in the recovery journal, with an explicit pending/error message.

On project open/create, editor fields reload from the project-specific recovery journal. Restored dirty notebook drafts, and manuscript drafts with a manuscript ID and section, automatically restart the same 800 ms routed save timer without requiring another edit. Incomplete manuscript metadata leaves the journal dirty for manual completion. The stored text is preserved even if the process closes before the timer fires, or a revision conflict prevents writing. The timer stops on project switch; the previous project's journal remains available on reopening. A successful write clears that surface's dirty flag and immediately checkpoints the journal. Data is bounded to 256 KiB serialized JSON per project; oversized drafts are rejected. The journal is app-local plaintext, with the same local workstation confidentiality expectations as other desktop state.

Validation on Windows: `cargo test -p researchweave-desktop --locked` now has 21 passing desktop tests covering journal restart, Unicode, project isolation, size bounds, repeated atomic journal replacement, recovery retry eligibility and both routed revision writes after simulated abrupt exit. The desktop build, Clippy (`-D warnings`) and formatting checks pass. The journal uses `ReplaceFileW` when replacing an existing file on Windows, avoiding the stale-journal failure caused by `rename` over an existing destination. Two consecutive complete Windows UIA runs then passed project creation/navigation, manuscript preview/record/inspect/export, notebook and manuscript edit-driven debounce saves, and independent abrupt process termination for each writing surface followed by reopen, restored editor text, automatic recovered retry without a fresh edit, and persisted manuscript/notebook verification. Autosave success feedback is written to status rather than replacing the manuscript/notebook inspection result surface, preventing the prior timer/result race.
