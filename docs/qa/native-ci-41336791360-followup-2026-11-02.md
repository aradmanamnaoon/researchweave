## Windows — exact diagnosed failure

Artifact `rust-windows-native-smoke-diagnostics`, retrieved under the disposable workspace
`target/qa/windows-native-41336791360/`, contains `windows-installed-uia.log`
and a captured PNG. The installed scenario passed create/open, protocol freeze,
real Windows PDF picker and PDFium page navigation. Immediately before starting
the F37 source-substitution test, the test failed at
`crates/researchweave-desktop/tests/windows-uia-smoke.ps1:814` with
`Unable to find type [RwUiaReadOnlySqlite]`.

**Confirmed test harness root cause:** the read-only WinSQLite C# here-string was
declared before that call but only registered by `Add-Type` in the F14 suite
near the end of the script. F37's earlier non-mutation oracle now calls it
first. The repair moves the single `Add-Type -TypeDefinition ...` execution
immediately after the here-string and before `Get-F14ProjectSnapshot`, preserving
the read-only SQL restrictions. A Python source-contract regression enforces
the initialization order.

**Local evidence after repair:** the C# type compiled on Windows, its `Scalar`
method read a disposable SQLite fixture successfully, and its `Rows` method
rejected a non-SELECT statement. The script PowerShell parser and Python native
source-contract suite passed. This does **not** prove the rest of the installed
Windows scenario passes; rerun the complete candidate after pushing.

freeze and verified physical receipt, then native quick-note creation and
pin/archiving controls. The first failure was
`scripts/qa/mission-atspi-navigation.py:1860`:
`RuntimeError: Archived note still visible in pinned/active view`.

The test had issued an AT-SPI action followed by a fixed short sleep, then
inspected the current accessibility nodes. An accepted action call alone does
not prove that the application persisted the requested card revision.
The remediation must require exact disposable SQLite card revision/content,
native scroll visibility and post-filter accessibility state, with finite
timeouts and no relaxation of negative assertions. Real installed acceptance
of the remediation remains pending.

the actual Pin/Archive/Restore buttons, then requires exactly one new
`notebook_entries` revision with the expected `pinned` and `archived` values
for each action (r2, r3, r4). It also requires the actual accessible card to
disappear from the previously active filter; a retained stale node triggers
a failure screenshot. The disposable read-only SQLite connections are closed
deterministically, including on Windows, so QA fixtures do not leak handles.
Four isolated regression tests cover positive incremental writes, rejected
non-writes, incorrect state/skipped revision and stale UI list visibility.
