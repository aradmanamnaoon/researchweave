### What the Linux/Xvfb GUI evidence proves

The native Linux test run left `docs/ux/screenshots/after-xvfb/12-context-ai-panel.png` and `13-context-preview.png`, showing the optional assistant and its local request-preview state. The underlying `scripts/ux/isolated-xvfb-gui-smoke.sh:279–301` performs actual X11/AT-SPI panel opening and Preview action paths (script naming has since changed to `13-context-ai-panel.png` and `14-context-preview.png`). This supports the **panel/preview GUI path**, not a completed local model call, cancellation timing, inference quality, citations, provider secret resolution, or any remote data transfer. Linux `after-xvfb/atspi.log` reports 56 nodes/55 named controls and `LINUX_AT_SPI_OK`, but this is **not** an Orca screen-reader test.

The path through `ai_chat` is a **local-model inference attempt**, not a confirmed deployed AI capability. When no approved local profile exists, the preview can still be inspected but **Run locally remains unavailable** with a reason. No source-grounded RAG query, model-generated trusted references, automatic manuscript changes, agent tool approval through this panel, or true assistant streaming has been demonstrated. The panel currently exposes project/page scoped text; per-selection evidence, exact source paragraphs and object-revision locking beyond the request equality check remain open work.

This is a **deeper target-affordance map**, not a claim that per-field or per-object actions all exist. A globally accessible source-bound preview is now implemented, but fine-grained selection/revision/source anchoring and real inference acceptance remain pending. Retain dedicated Agent and Providers for history, advanced tool configuration and debugging. Avoid scattering unlabeled duplicate icon-only buttons: use accessible verbs, action scope, visible processing and a clear return to current work object.

## Recommended contextual action contract

Every invocation should bind `(project_id, object_kind, object_id, object_revision_or_digest, selection, requested_capability, provider_policy)` to a **typed preview**. Read-only tasks display provenance and missing-source warnings; local writes show an explicit delta, expected current revision, effect classification and destination, then dispatch through the existing authority; network tasks show destination/provider, exact data categories and opt-in egress before transfer. An LLM output is untrusted task data, and a tool proposal stays inert until the host's exact-scope authorization. Avoid storing credentials in project documents or rendering raw proposal arguments in accessible status text. `AGENTS.md` requires opt-in remote transfer and offline-safe behavior.

For availability, the UI should distinguish: local deterministic explanation/preview, provider configured but untested, missing provider credential, remote provider intentionally disabled, and actual provider failure. Do not offer a button labelled *Generate with AI* unless an operational inference route exists; disable with a precise reason and an offline alternative as appropriate.

## Current gaps prioritized for follow-up

1. **P0 validate local inference:** Run against an approved local model with a genuinely reachable endpoint; test success, failure, timeout, cancellation, unauthorized profile, preview-invalidated-after-edit and no accidental mutations. The reusable panel and host run path exist; successful **end-to-end model inference is not yet verified**.
2. **P0 scope + provenance:** Bind exact source object ID, immutable revision or PDF text selection, source hash and verified excerpt for each relevant route rather than generic status text; show the current input, model activity, generated status, evidence and assumptions; never imply verified references where none were retrieved.
3. **P0 authority:** preserve project/revision/fingerprint checking and separate approve/execute/deny semantics already implemented in `main.rs:5310-5465`; test stale, denied, modified-arguments and cross-project proposals.
4. **P1 provider status:** explain local profile selection, offline/credential/connection differences and distinct network errors. Remote traffic stays blocked by the current local-only policy; adding it later requires independent explicit opt-in, redaction/cancellation/timeout, provider capability validation and measured cost where known.
5. **P1 context UI:** retain the reusable panel and its Preview/Run/Cancel affordances; add source selection, preview/diff/revert and focus restore, text wrapping and responsive width at minimum window size. Drafts must remain drafts until verified and approved. Existing Linux screenshots alone do not certify clipping fixes at 200% scale.
6. **P1 evidence-backed evaluation:** synthetic cited source, unverifiable question, stale dataset revision, missing provider, approval denial, failed runtime inference, long-running response and restart/recovery; verify in real Windows GUI and native macOS/Linux candidates.
