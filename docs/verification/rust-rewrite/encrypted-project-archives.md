# Encrypted project archive parity (2026-10-25)

The Rust project layer now implements the Python v0.1.2 `RWPENC1` encrypted `.rwproj.enc` format used by `src/researchweave/evidence/encrypted_archive.py`. The binary envelope is bounded to the native 256 MiB project archive limit, derives a 256-bit key with scrypt (N=32768, r=8, p=1), encrypts with AES-256-GCM, and authenticates the serialized metadata header as AAD. The header carries the project id, project revision, plaintext SHA-256 and plaintext byte count. Verification decrypts and authenticates the envelope, validates the inner `.rwproj`, and requires the inner project identity, revision and plaintext hash to match the authenticated header.

The project command router exposes `project.archive_encrypted`, `project.archive_encrypted_verify` and `project.restore_encrypted`. Export and restore are local writes that require one-use approval; export is revision guarded and restore is create-new/no-overwrite. Capability metadata marks `password` as a sensitive argument. Tests assert previews have no write effect and that the password is absent from command results and durable audit event representations.

Cross-language compatibility is exercised with `crates/researchweave-project/tests/fixtures/python-v012.rwproj.enc`, generated by the actual Python v0.1.2 implementation from the existing Python `.rwproj` fixture using the password `compatibility password`. Rust verifies and restores that Python-created encrypted archive, including its Persian project title. Native Rust round-trip tests cover wrong passwords, ciphertext tampering, identity mismatch checks and no-overwrite restore.

Desktop pages **Backups** and **Recovery** now call the routed project operations. Backups supports portable and encrypted export/verification using an absolute user-selected path. Recovery performs a minimal read-only archive preflight to establish the UUID authority scope, then dispatches the actual restore through `CommandRouter`, creates a new project directory and opens the recovered project. Password fields use password input mode and are not persisted.

Verification completed locally on Windows: `researchweave-crypto` tests 6/6 pass, `researchweave-project` tests 16/16 pass, their warnings-denied Clippy gate passes, and the desktop backup/recovery helper round trip passes inside the desktop suite. Literal Windows UIA interaction with the newly added Backups/Recovery controls has not yet been rerun after these controls were added.
