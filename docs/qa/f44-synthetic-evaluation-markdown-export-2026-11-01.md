# F44 synthetic evaluation technical receipt export

Source: `crates/researchweave-analysis/src/extraction_evaluation_export.rs` exports `evaluate_and_render_markdown(EvaluationRequest)`.

The wrapper first invokes the existing strict `evaluate` flow. It refuses non-synthetic requests, changed supplied frozen gold/prediction commitments, mismatched content SHA-256, declared held-out/training overlaps, invalid or out-of-bounds anchored spans, duplicate slots and other evaluator guards. It never trains a model, verifies independent gold custody or writes to disk/network.

After successful synthetic evaluation, the output contains a deterministic UTF-8 Markdown technical receipt with the report schema/ID, supplied synthetic predictor label, canonical evaluator provenance SHA-256, frozen input commitments, whole-cohort and field-level TP/FP/FN/TN/abstention, defined/undefined precision-recall and selective risk, and explicit synthetic/no-model-validation limitations. Unique field rows and byte output are bounded; Markdown/HTML-sensitive field text is escaped. Individual source excerpts, gold labels and predicted values are deliberately omitted. An additional SHA-256 of exact exported Markdown bytes is returned so a future host can verify the payload before any physical approved export.

The result is a data-minimized synthetic **technical fixture receipt**, not peer-reviewed evidence, real model performance, a calibration guarantee, an external preregistration, or a production evaluation dashboard. No physical export or project-bound human adjudication is wired. The ledger remains **PARTIAL**.

Initial unit tests cover deterministic exact SHA, Unicode fixture, Markdown injection escaping, synthetic-only label, absence of source and individual values, analytically known 1-of-1 exact anchored result, and refusal of real/mutated-gold inputs. Native project-scoped adjudication and physical file-no-overwrite still require separate implementation and acceptance.

## New bounded native Diagnostics demonstration

The native Slint Diagnostics page now includes a **collapsed opt-in F44 synthetic fixture panel**. A user can insert a programmatically generated, clearly labeled synthetic one-slot fixture or edit a typed JSON example and run an explicit offline, no-write preview. `crates/researchweave-desktop/src/f44_synthetic_evaluation.rs` checks input <=128 KiB, at most 1,000 sources/gold/prediction slots, typed schema, `synthetic_fixture=true`, externally supplied gold/prediction commitments and exact source anchors through the existing evaluator, output <=64 KiB, and the SHA-256 of the actual generated redacted Markdown. The UI shows separately labeled source-provenance and Markdown hashes and clears any old result after an edit, failed evaluation, project change, or explicit clear. It contains no file-write, remote request, model call, or project mutation path. The flag `synthetic_fixture=true` is **a caller assertion and cannot prove that pasted content is actually synthetic, properly licensed or non-sensitive**; users must not paste private real research data here. Nothing establishes blinded human gold custody or real model performance.

Two Rust adapter tests assert exact deterministic round-trip output, omission of the source text, and rejection of invalid/oversized/altered fixture inputs. An isolated Linux Xvfb/AT-SPI scenario was authored to click real native controls, read back the actual Markdown through the private X11 clipboard, independently rehash it, refuse malformed input, and assert the original disposable project's SQLite event history did not change. Both the candidate and release native Linux CI workflows require the positive and negative F44 markers; these **are requirements for a future exact-source installed pass, not presently verified acceptance**. Full production evaluation, real human-reviewed held-out cohorts, model performance, input-data privacy classification, project-backed custody, and physical no-overwrite export remain missing.
