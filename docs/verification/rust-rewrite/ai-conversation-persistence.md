# Rust AI durable conversation store — 2026-10-25

The AI crate now exposes `conversations::ConversationStore`, opened on a host-chosen file path within an existing directory. It persists conversations per project and explicit conversation ID; supports create, list, append of `system`/`user`/`assistant` text, and bounded recent history in chronological order. Data is stored in a versioned-by-structure JSON snapshot, with a temporary file, sync and OS replace on writes; a mutex serializes mutations within one instance. Message size is at most 1 MB, history reads at most 256 messages, and per-conversation capacity is 10,000 messages. Duplicate conversation IDs are rejected. Project isolation and restart persistence have a test fixture including Persian Unicode.

The store deliberately does not persist provider profiles, credentials, tool calls, tool execution arguments, or network traffic. It never executes proposals and does not claim live health or streaming. **Important privacy limit:** conversation text is plaintext and could contain user-entered secrets; the host must choose an access-controlled location, and users should not enter credentials in prompts. This is not encrypted-at-rest storage. Only one writer instance per path is supported; the host must prevent concurrent processes from opening the same file for writes. No host operation handler integration or automatic conversation writes from chat are claimed yet.

The Python baseline uses SQLite and has more sophisticated metadata and tool-approval state. The Rust JSON store is intentionally narrower, isolated from host schema migrations. Do not equate it with full Python parity.

The host `AiOperationHandler::with_conversations` now production-links a host-opened store into the registered `assistant.conversation.create`, `assistant.conversation.list`, `assistant.message.append`, `assistant.history` and `assistant.context` operations. The `DispatchContext.project_id` is the only source of project identity, never a caller-supplied project ID. The two writes are registered `LocalWrite` and therefore require CommandRouter approval/audit. Read operations are `Read`. Write previews are side-effect free; the returned preview contains no message text. A missing store returns `UNSUPPORTED_CAPABILITY`. Context returns a latest-contiguous chronological window bounded to 32,000 UTF-8 bytes from the selected recent history, **not** AI-generated summarization or Python context-compaction parity. Prompt template add/render is not registered because durable prompt template validation and policy have not been implemented.

Verified on Windows with `cargo fmt -p researchweave-ai`, `cargo test --locked -p researchweave-ai` (**15/15 passed**) and `cargo clippy --locked -p researchweave-ai --all-targets -- -D warnings` (**passed**). The host-dispatch regression proves preview leaves storage unchanged, unapproved writes are denied, approved writes persist after reopening, project scoping holds and zero model network calls occur. No root lockfile change was necessary in this run.
